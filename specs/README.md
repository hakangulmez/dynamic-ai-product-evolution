# Specifications

Each `SPEC-XXX` defines one implementation contract. Status values:

- Draft
- In review
- Accepted
- Implemented
- Frozen
- Superseded

A spec must define objective, inputs, outputs, rules, failure modes, tests, eval criteria, and acceptance thresholds. Code changes must cite the governing spec.

## Current groups

- `SPEC-001`–`SPEC-007`: historical company-universe construction and source corpus. `SPEC-001` includes the multi-axis Tier A/B/C classification, negative audit, lineage, and release-freeze contract.
- `SPEC-008`–`SPEC-013`: product, capability, task, role, and longitudinal matching.
- `SPEC-014`–`SPEC-019`: dated frontier baseline, measurements, and aggregation.
- `SPEC-020`–`SPEC-021`: evaluation and analysis outputs.
- `SPEC-022`–`SPEC-025`: evaluation data model, deterministic validation, immutable run comparison, and local review console.
